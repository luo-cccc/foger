## 四、过程问题记录（诚实披露）

1. **第 1 集误判 audit-failed**：runner 硬区间残留所致（见二），修复后 `write sync` 重判 ready-for-review，无需重写内容。
2. **第 4、7 集各一次 writer 输出解析失败**：deepseek-v4-flash 输出以 `=== PRE_WRITE_CHECK ===` 前导开头且 JSON  malformed（候选提取全部落空），手动 `write next` 重试即成功。与首测结论一致：flash 模型输出抖动是残余风险，当前失败时不落盘原始输出，建议后续把解析失败的原始响应存到 runtime 目录便于诊断。
3. **伏笔债务 warning 贯穿中后期**（H003/H005/H006/D001 反复"已逾期"）：不阻断，完本门禁判定 6 条 deferred 属合法留白，压力提示按设计工作。
4. ** inkos.json 里 `configSource: "studio"` 时 CLI 不读文件内 baseUrl/model**：需用 `INKOS_LLM_BASE_URL/INKOS_LLM_MODEL` 环境变量覆盖才能跑通 CLI。首测大概也靠环境变量；建议文档补一句或在 CLI 侧给出更明确的报错（当前报 "Invalid url" 指向不明确）。
